# 原设计、项目进度与新增需求交接

> 对照文档：`CENTRAL_PANEL_DESIGN.md`、`CENTRAL_PANEL_DEVELOPMENT_PLAN.md`
> 对照日期：2026-09-06

本文把原始设计和开发计划拆成三类：已经完成、尚未完成、开发过程中新增或替代的项目。原始设计文案仍保留在项目根目录，本文件是当前实现的判断，不覆盖原文。

## 1. 原设计的核心目标

原设计要求建立一个轻量中央面板，集中读取多个 X-Panel 节点的节点状态、Inbound、Client、累计流量和到期时间，并提供用户、节点、线路、出口 IP、成本和财务视图。中央服务不直接接管 Xray 配置，Agent 负责本机采集，业务管理员负责中央侧运营信息维护。

原设计中的关键不变量仍然有效：

- 业务用户按 Inbound 统计，不按 Client 统计；
- Agent 只读累计流量，不调用清零接口；
- 同步幂等、失败可重试、历史数据可解释；
- 节点离线或 Inbound 暂时缺失不应删除历史；
- Token、密码和 X-Panel 凭据不能明文进入中央日志或数据库；
- HTTPS、备份、恢复和回滚属于发布门禁，不为赶进度删减。

## 4. 开发过程中新增或替代的项目

这些内容不在最初计划的原始颗粒度中，或是根据实际运营反馈改变了实现方式。

### 4.1 用户路径替代线路关系

原计划把线路关系作为用户分配的中心。实际运营确认后，日常流程改为“用户来自哪个线路机、是否经过哪个落地机、固定使用哪个出口 IP”。因此新增 `user_paths`，让管理员直接为用户选择三种互斥模式；旧线路表和接口只做兼容与历史，不作为新分配前置条件。

### 4.2 出口 IP 三种来源

原设计主要面向落地机出口，后续新增：线路机直出出口和不挂在任何 VPS 上的独立 S5。数据库增加来源类型、所属节点和绑定位置校验，前端按来源筛选。

### 4.3 业务用户与落地基础设施边界

新增 `user_path_assets` 聚合接口和 `infrastructure` 标识：落地机 Inbound 只作为路径资产，不能出现在用户列表；无首次同步时显示 pending，而不是把空列表误认为没有资源。

### 4.4 节点管理体验

新增管理地址模型，允许域名、端口和路径；接入向导自动填充 X-Panel 地址和 API 路径；出口 IP 使用动态增加输入框；节点删除改为永久清理节点拥有的数据，但不自动清理业务用户；节点 Key 可由中央生成。

### 4.5 一键 Agent 部署

新增短期安装 Token 和 Ubuntu/Debian amd64 在线安装脚本：前台生成一行命令，目标机器本地输入 X-Panel 账号密码，凭据不上传中央。手动 YAML/systemd 仍作为故障兜底。

### 4.6 累计流量增长曲线

原先仅有流量快照数值，新增累计总量增长曲线和时间范围切换；速率只用于悬停辅助，不改变“累计使用总和”的统计口径。

### 4.7 月付/年付和续费检测

新增年付周期、周期金额、收费记录和续费候选。Agent 检测到期时间延长只能提出候选，管理员确认后才形成收入，避免把管理员临时改时间直接当成收费。

### 4.8 事件中心和强提醒

“同步事件”重构为事件中心。立即同步请求降级为内部调度记录；真正对运营有用的续费待确认、节点离线、同步失败、流量回退和 Inbound 归档进入事件流，并支持红点、未读/未处理和操作。

## 5. 已废弃或仅兼容保留的设计

- 线路模板不是新用户分配的必需步骤；
- 落地 Inbound 不再创建业务用户；
- 删除节点不会自动删除孤立业务用户；
- `public_ip` 仅为旧数据兼容展示，新流程使用 `management_url` 和出口资产表；
- 立即同步不再作为运营事件主列表内容；
- 当前版本不做中央直接写入 X-Panel 的用户/Client 创建、续期或删除。

## 6. 下一阶段建议顺序

1. 修复并记录公网测试中“Agent 日志成功但页面状态”的实际状态链路；
2. 用一台线路机、一台落地机和一个独立 S5 做三种用户路径验收；
3. 对照 X-Panel 真实账目验证月付、年付、续费候选和事件处理；
4. 完成备份/恢复、中央重启、Agent 重启和二进制回滚演练；
5. 灰度观察 3–5 天后再打正式版本标签。
