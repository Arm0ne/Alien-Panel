# 性能优化记录

本文记录 Alien-Panel 最近已经完成的性能优化、验证结果和生产部署口径。文档中的“已完成”表示已经合并到 `main` 并包含在当前发布包中；生产环境的实际耗时仍需要更新服务器后重新测量。

## 优化背景

生产环境的数据库统计显示，流量历史是当前数据库的主要体积来源：

- `traffic_snapshots`：323,801 行；
- `sync_runs`：62,674 行；
- 用户：40 个；节点：14 台；用户 Inbound：68 个；Client：184 个。

性能基线中，总览接口在短缓存命中时约为 163 ms；缓存过期后的冷查询约为 3.61 s，其中服务器等待约为 3.60 s。旧的流量查询计划包含以下特征：

- 按 Inbound 查找快照后，再执行相关的 `MAX(collected_at)` 子查询；
- 使用 `CORRELATED SCALAR SUBQUERY`；
- 最后使用临时 B-Tree 完成排序。

这说明总览的主要瓶颈在流量历史查询，而不是服务器 CPU、内存或磁盘空间不足。

## 已完成的优化

### 1. 减少重复索引和改善同步记录查询

迁移 `022_performance_indexes.sql` 已增加 `sync_runs` 的组合索引，用于按节点、状态和时间查找同步记录，也支持全局最近一次成功同步时间查询。

迁移 `023_drop_redundant_traffic_index.sql` 删除 `idx_traffic_snapshots_inbound_collected`。`traffic_snapshots` 的 `UNIQUE(inbound_id, collected_at)` 已经提供等价索引，因此删除重复索引不会删除业务数据，也不会取消唯一约束。

023 迁移使用 `DROP INDEX IF EXISTS`，用于兼容已经执行过旧版 022 迁移的数据库。服务启动时会自动、幂等地执行迁移。

### 2. 总览复用同一份 Inbound 元数据

总览请求现在只读取一次符合条件的用户 Inbound 元数据，随后复用于：

- 当前请求时间范围的流量统计；
- `today` 流量统计；
- 本月流量统计；
- 用户流量排行。

这避免了同一次总览请求重复读取相同的 Inbound、节点和 Client 信息。

### 3. 重写总览流量查询

新的查询使用分阶段 CTE：

1. `eligible`：筛出有效的用户 Inbound；
2. `range_rows`：只读取请求时间范围内的快照；
3. `baseline_times`：为每个 Inbound 找到时间范围开始前的最后一条快照；
4. `baseline_rows`：读取这些基准快照，并与范围内数据合并。

这样每个 Inbound 最多补充一条范围开始前的基准快照，避免旧查询对范围内的每一条快照重复执行历史 `MAX()` 查询。重置检测、增量计算、趋势、节点排行和用户排行的 API 字段保持不变。

### 4. 保留短缓存和后台状态维护策略

此前已经完成的性能策略继续保留：

- 总览接口使用 10–30 秒短缓存，频繁打开页面时直接复用结果；
- 用户、节点、财务等 GET 请求不再同步执行完整状态刷新；
- 状态刷新由后台维护任务负责，页面请求只读取数据库状态。

这些策略降低了页面请求与 Agent 同步任务之间的相互等待。

## 安全性和业务影响

本轮代码没有修改 API 响应字段、用户状态口径、节点同步流程、财务记录或流量写入逻辑。数据库迁移只删除重复索引并保留唯一约束，业务数据不会被删除。

流量统计的读取范围从“历史数据加每条记录的相关子查询”改为“请求范围加每个 Inbound 一条基准记录”。现有测试已验证总览业务范围、重置快照、节点排行、用户排行和 Client 在线时间等逻辑。

源码层面可以安全发布，但任何数据库查询优化都应在生产更新后重新观察冷查询耗时、同步期间请求等待和统计结果。当前没有把生产环境的最终耗时下降写成已验证结论。

## 生产更新

更新前先保留现有数据库备份和 Docker 数据卷，然后执行：

```bash
curl -fsSL https://raw.githubusercontent.com/Arm0ne/Alien-Panel/main/install.sh \
  | sudo bash -s -- \
  --repo https://github.com/Arm0ne/Alien-Panel.git \
  --ref main \
  --domain panel.panlai.me
```

升级会保留 `/opt/alien-panel/.env` 和 `alien-panel_central-data` 数据卷。中央服务启动后会自动执行 023 迁移。

更新后建议在浏览器 Network 中记录：总览首次打开、短缓存内再次打开、缓存过期后的再次打开，以及 Agent 同步期间的请求耗时，并与本文件的基线对比。

## 后续候选项

以下内容属于后续优化方向，目前不包含在本次发布中：

- 将不同 Agent 的 heartbeat 和 sync 错开，并增加随机时间偏移；
- 对分钟级流量历史执行保留和小时/天级汇总策略；
- 让事件中心轮询只请求汇总接口，打开弹窗时再读取事件列表。

这些改动涉及调度、数据保留和接口交互策略，应在新的基线数据基础上逐项实施。
