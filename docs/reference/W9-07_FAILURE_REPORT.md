# W9-07 故障与重试验证报告

更新时间：2026-09-03

## 范围

本阶段验证 Agent 与中央服务在节点离线、X-Panel/中央接口超时、暂时性 5xx/429、重复同步和并发节点同步时的行为。验证目标是保留最后一次有效数据，不产生负流量，不因失败快照触发 Inbound 归档，也不因重试产生重复资源。

## 实现的故障策略

- Agent 中央客户端和 X-Panel 客户端对网络错误、HTTP 超时、408、425、429 和 5xx 执行有界重试；业务错误和认证失败不会盲目重放。
- 默认退避为最多 4 次尝试，失败后依次等待约 30 秒、2 分钟、10 分钟；等待受 Agent 上下文取消控制。
- 同一中央逻辑请求在重试期间复用 `X-Request-ID`；同步载荷继续使用同一 `sync_id`，依靠中央幂等约束避免重复写入。
- X-Panel 遇到 401 只重新登录一次；登录暂时性网络故障也使用同一退避策略，错误凭据仍进入登录失败退避。
- 节点离线只刷新健康状态，不删除节点、Inbound、Client、成本或流量快照；失败同步不会增加 Inbound 缺失计数。

## 自动化验证

| 场景 | 验证内容 |
| --- | --- |
| 中央 503/超时 | 失败后重试，成功时保持同一请求 ID；客户端超时按策略再次请求 |
| X-Panel 503/超时 | 列表和状态请求重试；应用层失败不重复请求 |
| 登录超时 | 登录请求按策略重试，最终失败进入登录退避 |
| Agent 取消 | 退避等待期间取消上下文，Runner 立即退出，不残留后台等待 |
| 节点离线 | 节点变为 `offline`，最后 Inbound 和快照仍存在 |
| 重复同步压力 | 24 个并发相同 `sync_id` 请求只产生 1 条同步记录、1 条快照、1 个用户和 1 个 Client |
| 并发节点 | 4 个节点同时同步均成功，彼此不共享认证或数据 |
| 流量回退 | 累计值下降只记录一次 `traffic_reset`，不产生负数 |
